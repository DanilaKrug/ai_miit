# П2. Ночная нормализация пачки реестров

## Команда

Олег Сапрошин, Владимир Матвеенко.

## Задача

Технолог вечером складывает в папку пачку реестров заявок от разных клиентов, каждый в своей
раскладке. Ночью воркер разбирает их в единое хранилище, а утром технолог получает
уведомление и отчёт о качестве: сколько файлов и строк принято, сколько отброшено и почему,
какие станции не удалось распознать. Агент нужен ровно там, где раскладка файла заранее
неизвестна: он смотрит на первые строки, решает, где заголовки и какая колонка что значит,
и дальше вызывает инструменты нормализации.

## Вход

Папка с файлами Excel и CSV в неизвестных раскладках, команда «поставить пачку в очередь», запрос статуса по номеру задачи.

## Выход

1. Заявки в хранилище в едином виде.
2. Утренний отчёт о качестве: принято файлов и строк, отброшено и почему, нераспознанные станции, дубли. Отчёт лежит файлом Markdown в папке результатов рядом с пачкой и привязан к номеру задачи в SQLite, чтобы его можно было запросить повторно.
3. Уведомление о завершении: краткая сводка из отчёта и путь к полному файлу. Канал на выбор команды: почта или Telegram.
4. Журнал обработанных файлов, чтобы повторный запуск не грузил файл дважды.

## Стек технологий

- Python 3.11+.
- LLM через прокси курса (OpenAI-совместимый API), модель на выбор команды.
- Логирование вызовов инструментов: файл, SQLite или Langfuse.
- pytest для тестовых кейсов.
- Очередь задач и хранилище: SQLite.
- Воркер: отдельный процесс, цикл или APScheduler; cron не нужен.
- Разбор Excel и CSV: openpyxl или pandas.
- Уведомление: консоль, почта или Telegram на выбор.
- Не требуется: распределённые очереди вроде Celery.

## Данные

### Реестры заявок `data/registry_01..20.xlsx`

Двадцать Excel-файлов с заявками на подачу вагонов от семнадцати клиентов, всего 453 заявки.
Нарезка из витрины заявок ГУ-12 (`V_DM_GU12.csv`) набора курса.

| Раскладка | Как выглядит файл |
|---|---|
| L1 | четыре строки шапки документа, объединённая ячейка «Маршрут» над двумя колонками, заголовки таблицы только в шестой строке |
| L2 | заголовки в третьей строке и названы иначе («Заказчик» вместо «Клиент»), род вагона словами |
| L3 | заголовков нет совсем, колонки в другом порядке, после таблицы подпись исполнителя |
| L4 | шапка в две строки с объединёнными группами, внутри таблицы пустая колонка-разделитель |
| L5 | таблица начинается с колонки C, станции записаны как «код название», часть дат настоящие даты Excel, часть текст |
| L6 | первый лист без данных, таблица на втором; груз и род вагона в одной ячейке через «/», маршрут одной ячейкой через тире |
| L7 | заголовки строчными буквами с переносами строк, клиент указан только в первой строке над таблицей, после каждых десяти заявок пустая строка |

Поле «дата» во всех файлах означает день снимка заявок. Периода подачи в витрине нет,
поэтому его нет и в файлах.

### Справочник станций `data/stations.csv`

300 станций десяти дорог: код, название, код и название дороги, в каких витринах станция
встречается. Все станции реестров в правильном написании есть в справочнике; опечатки нормализуются
к нему.
